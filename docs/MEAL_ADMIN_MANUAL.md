# 便當管理員操作手冊

日期：2026-10-10

本手冊涵蓋便當管理與社員名冊操作。LINE 授權與實體出單機須另依正式設定及設備完成驗收。

## 1. 管理員登入與日常入口

使用具有管理員角色的帳號登入。一般使用者看自己的訂單，管理員可進入會員、便當、訂單及財務管理。

日常從「便當營運管理」開始，先查看「訂單查詢與待辦」，再按需要進入「退單審核」或「場次與核銷」。管理權限不會略過已取餐、金融結果或資料一致性的檢查。

## 2. 查看已註冊使用者及確認社員

入口：`/admin/users` 的「會員管理」。

1. 以姓名、Email、會員編號或社員編號查詢。
2. 核對註冊使用者資料及目前身分。
3. 非社員需要升級時，按「線下確認並設為社員」。
4. 填入線下確認日期、原社員編號及核對說明或收據參考；沒有原社員編號時由系統編號。
5. 勾選「我已核對本人身分及線下入社／繳費資料。」。
6. 按「確認授予正式社員資格」。

系統保存確認日期、處理管理員及理由。線下確認不會虛構一筆線上扣款；已有已付款或退款中的線上入社案件，須先核對避免重複確認。

## 3. 用訂單編號查詢與查看明細

入口：`/admin/meals` →「訂單查詢與待辦」。

1. 輸入訂單編號，按查詢；也可輸入姓名或 Email。
2. 需要縮小範圍時，設定取餐日期起訖、午餐／晚餐、取餐時刻、付款、履約、發票或最新退單審核狀態。
3. 查看查詢結果，展開訂單明細，可看餐點、數量、選項、金額、發票及申請理由。
4. 待審訂單可直接按「審核這筆退單」，系統會帶入編號。
5. 退款或發票需要處理時，可直接進入該筆訂單的原管理頁。

日期篩選使用台灣日期，優先依實際選擇的取餐時間判定；沒有指定取餐時刻的舊訂單，以場次開始時間顯示並標示。跨場次結果依取餐時間排序，有分頁，查詢不會更改訂單。

## 4. 四類營運待辦

- **退單待審**：有尚待管理員決定的退單申請。
- **退款待處理**：退款排隊、退款失敗或付款晚到需要退款等訂單。
- **發票待處理**：開票或作廢等工作失敗，需要核對的訂單。
- **今日待取餐**：台灣今天已付款且仍可履約、尚未取餐的訂單。

每筆訂單在同一類只計一次。待辦數字不是餐點份數或金額；點選待辦會清除原篩選，重新列出對應訂單。畫面會定時更新，也可手動重新整理。

## 5. 核准或拒絕退單

入口：「退單審核」，預設列出待審申請。

1. 用訂單編號或 Email 找到申請。
2. 核對申請原因、取餐時間、餐點、付款、發票及履約狀態。
3. 決定「核准退單」或「拒絕退單」。
4. 填寫審核理由；使用者會看到這段回覆。
5. 確認送出，等待系統結果後再處理下一筆。

核准會取消整張訂單；已付款訂單依原付款通路送退款，發票依既有作廢或調整流程處理。製作中或待取餐餐點的份數不重新開放販售。拒絕後，原訂單繼續依目前狀態處理。

申請與金融結果分開保存；「已核准」不等於退款已入帳。已取餐、已結束履約等狀況可能禁止核准，請按系統原因處理，不要以重複送出或修改付款狀態代替退款。

## 6. 建立餐點、排程及場次

1. 「餐點主檔」建立餐點名稱、介紹、價格及稅別。
2. 「每日午晚餐排程」管理午餐／晚餐、供餐日期與時段、餐點及容量。
3. 「場次與核銷」建立草稿場次，加入餐點、份數、取餐地點與時間。
4. 確認後發布。系統只允許使用者在取餐日前一天的有效窗口下單。
5. 午餐預約時點為 11:00–13:00、晚餐 16:30–18:00，每半小時一個時段；場次可縮小實際窗口。

新生成場次保留最後取餐時點後的半小時供現場核銷。因此「最後可預約時間」與「供餐結束時間」不同：最後可選 13:00 的標準午餐，核銷窗口可到 13:30；晚餐同理可到 18:30。

尚未成立訂單且狀態允許的場次，可按「手動編輯場次」。已有訂單時，系統保護原取餐安排與訂單快照，不能直接更改原場次。取消場次須填原因。

## 7. 現場取餐核銷

1. 找到正確日期與餐別的場次，確認地點。
2. 按「開放取餐」。
3. 在核銷欄輸入使用者六位取餐碼，或掃描後貼入完整 QR token。
4. 按「確認核銷」。
5. 出現該訂單已完成取餐訊息，才交付對應餐點。

同一份憑證不能重複取餐。取消、退款或不在核銷窗口的訂單，系統依狀態限制使用。收班時確認待取餐訂單，再結束場次。

## 8. 財務、退款與發票

入口：`/admin/finance` →「銷售統整」／「訂單明細」。

1. 選開始與結束日期，包含所選日期當天，使用台灣時區。
2. 可按「今天」「本週」「本月」帶入區間；本週從週一開始。
3. 若需要找特定訂單，輸入訂單編號、姓名或 Email。
4. 查看統整中的期間收款、已完成退款及淨收款，或切到「訂單明細」。
5. 明細每頁 20 筆，包含買家、社員身分、餐點與加選、數量、單價、小計、總額、稅額、期間收款／退款／淨收款、付款、取餐、審核、發票狀態與票號。
6. 需要處理個別訂單時，使用明細的訂單管理入口；需要保存報表時，匯出全部符合條件結果的 CSV。

收款依實際付款完成日計算，退款依實際退款完成日計算，待審或待退款不先扣收款。跨期退款歸入完成退款的日期。餐點份數與小計依首次付款訂單計算，包含後續退單的原銷售；重複付款不重複計餐點份數。

財務頁只顯示便當銷售，已移除結餘分配入口。舊資料保留供歷史核對；不要將便當統計視為其他商品與團購的總營收。

退款失敗或發票異常時，先確認供應商結果及系統紀錄，再使用該訂單可用的重查、退款或發票調整操作。不要以核准退單的時間當作實際退款入帳時間，也不要重複發出相同金融請求。

## 9. 廚房備餐與列印

入口：`/admin/kitchen` 的「廚房出單」。

1. 選取餐日期及午餐／晚餐。有效已付款訂單依取餐時間排列，包含訂單編號、餐點、數量及客製選項。
2. 有待審退單時，先核對提醒及申請原因。前一天已截單的場次仍能備餐。
3. 依實際進度按「開始製作」，完成後按「待取餐」。狀態不能倒退。
4. 選擇訂單並開啟 80mm 列印預覽。補印會標示補印，開印前會再次核對訂單有效。
5. 按列印後，在瀏覽器列印視窗選擇設備及紙張。列印視窗開啟不代表紙張已成功印出；此版本不顯示虛構的成功次數。

廚房清單排除未付款、已取消、已取餐及已結束供餐訂單。實體出單機品牌與連線方式尚未決定，因此尚未啟用自動送單。

## 10. LINE 與其他入口

- **LINE 登入**：仍需站方完成 Channel、回呼網址及帳號連結設定，並走完實際授權驗收。管理員不需要保管使用者 LINE 密碼。
- **廚房出單機**：設備型號與連線方式未確定；目前使用上述瀏覽器列印流程。
- **改單與部分退單**：目前沒有一般使用者自行改取餐時間、改餐點或部分退款的入口；例外需求由管理員核對。

## 11. CSV 匯入既有社員名冊

入口：`/admin/social` →「社員名冊」→「匯入社員名冊」。

1. 按「下載 CSV 範本」，填入社員編號、姓名、Email、手機。股金與股數可留空，預設為 0。
2. 在試算表中將手機欄設為文字，保留開頭的 0；也接受 `+886` 格式。股金、股數需為非負整數。
3. 儲存 CSV，使用 UTF-8 或 Big5。每次最多 500 筆、2 MB，欄位名稱依範本，也接受對應英文名稱。
4. 按「選擇 CSV 檔案」。先核對預覽中的姓名、聯絡方式與股籍資料；此時尚未新增任何社員。
5. 若有錯誤，依 CSV 列號修正原檔，再重新選檔。檔案內重複、既有名冊或會籍使用的社員編號均不能匯入。
6. 全部通過後按「匯入 N 筆社員」。成功時顯示匯入筆數並更新名冊；其中一筆衝突會讓整批取消寫入。

只接受範本六個欄位及中文／英文對應名稱，不會忽略未知欄位。既有紀錄不覆蓋；股籍修改使用原有「編輯股金／股數」。姓名、Email、手機沿用加密儲存，CSV 匯入不建立登入帳號，也不產生付款或退款。社員後續仍透過既有名冊核對流程認領帳號。
