# 管理員退單與電話聯絡

日期：2026-10-23
狀態：本機實作，尚未部署；正式站行為不因本文件改變。

## 消費者與客服

便當、日常選品與共同購買的消費者均改為電話聯絡退單。前台不再提供取消或送出退單申請；已存在的退單審核紀錄仍可查閱。電話聯絡本身不會改變訂單、庫存、付款或發票。

管理員於平台設定維護 `support_phone`，透過公開 `/v1/platform` 提供給訂單介面。號碼留空時顯示「退單聯絡電話尚未設定」，不產生可撥號連結，也不使用測試號碼。日後填入有效號碼才顯示 `tel:` 連結。允許區碼、國碼、空格、括號與連字號，限制為 7–15 位數字；舊管理介面沒送此欄位時保留原設定。

## 管理員操作

管理員在訂單或便當查單介面選擇「辦理退單」，核對訂單與狀態、填寫原因後確認。後端重新檢查權限與履約狀態，將退單紀錄、庫存調整、退款工作與稽核一起提交。重複送出已完成的同筆退單不會再退款或釋放庫存。

商品與共同購買在尚未交付且物流未進入不可逆狀態時，可由管理員處理整張退單。便當沿用供餐期限與取餐限制；已取餐、逾時未取或餐期結束不可直接退單。製作中或待取餐的便當退單後保留已製作份數，避免重新販售。

既有待審申請保留管理員核准／拒絕入口及歷史紀錄。新電話退單不要求消費者另送申請；記錄管理員操作者與理由。

## 金流與發票狀態

| 原訂單狀態 | 退單後 | 後續處理 |
| --- | --- | --- |
| 未付款 | 取消履約、釋放有效保留、付款標為逾期 | 不建立退款或新發票；晚到付款沿原補償流程處理 |
| 線上付款成功 | 取消履約、依原交易建立退款工作 | `refund_pending` 不代表退款完成；由原金流查回確認 |
| 現場付款已收款 | 取消履約、建立現場退款待辦 | 管理員實際退還後確認，才標記 `refunded` |
| 退款失敗／結果未明 | 保留退款狀態與待辦 | 沿既有補查與人工核對流程，不以重按退單重送退款 |

取消訂單不會直接作廢發票。只有後端確認全額退款完成後，才沿既有發票調整流程處理；汎宇發票須查回作廢狀態才顯示已作廢。現場發票不轉成雲端發票，也不呼叫雲端作廢。既有原交易、原供應商及送出不明時只補查的保護繼續適用。

## API

| API | 權限與用途 |
| --- | --- |
| `POST /v1/orders/{id}/admin/cancel` | 管理員整張商品／共同購買退單；body `{reason}` |
| `POST /v1/admin/meal-orders/{id}/cancel` | 管理員整張便當退單；body `{reason}` |
| `POST /v1/orders/{id}/cancel` | 舊消費者入口，已登入請求回 403，無退單副作用 |
| `POST /v1/meal-orders/{id}/cancel` | 舊消費者入口，已登入請求回 403，無退單副作用 |
| `POST /v1/meal-orders/{id}/cancellation-requests` | 舊申請入口，已登入請求回 403，無退單副作用 |

管理員舊審核端點仍保留。未登入請求沿既有驗證回應處理；消費者 `available_actions` 不再回傳取消或申請取消。

此改動不新增資料表，使用既有退單紀錄、稽核、退款及 outbox。前後端應一起發布；舊客戶端送出的取消／申請請求會收到聯絡合作社的拒絕訊息。本機測試使用隔離資料與模擬供應商，未執行正式退款、開票或作廢。

## 同時操作與驗證

隔離 PostgreSQL 測試重現了付款／退款回傳先鎖付款交易、退單先鎖訂單造成的死結。訂單相關流程改為一致的鎖定順序：餐期或共同購買 → 訂單 → 付款交易 → 退款；建立付款、單筆退單、原審核、整團取消、金流回傳及退款 worker 都依同一順序協調。Worker 在寫入「已開始送出退款」標記並提交後，重新取得鎖及最新狀態，仍保留結果未明只補查、不自動重送退款的機制。

驗證包含消費者舊入口拒絕且無副作用、管理員權限、原因驗證、舊申請相容、商品庫存與共同購買數量只回補一次、便當已製作產能保留、晚到付款、現場退款確認、退款完成後才調整發票，以及取消與取餐／付款／整團取消的雙向競爭。53 個 PostgreSQL／現金併發案例均有通過紀錄；152 項金融回歸通過。臨時資料庫已清理。

瀏覽器新流程 12 項通過，包含三通路電話入口、空電話與錯誤恢復、電話存入／清空、管理員確認、現場退款、舊申請與 390px 放大顯示；原便當取消案例已更新為電話聯絡且保留取餐 QR。TypeScript 與前端建置通過。

最終 `pytest tests audits -q`：1,817 項通過、4 項略過；前端單元／稽核 76 項通過。本機 TLS 測試以隔離 HTTPS server 驗證，沒有對正式供應商發送交易。
