# 社員核對與直接登入入口

日期：2026-11-06

## 操作

依使用者確認，不另外寄送社員查詢結果信。「不確定是否是社員？」與「我是社員」共用既有社員入口。

- 首次使用網站的既有社員：輸入名冊登記的電話號碼及 Email → 同意資料使用 → LINE 授權 → 完成原信箱的認領驗證 → 啟用社員資格。
- 已有網站帳號：按「曾用 LINE 登入，直接登入」，使用已連結的 LINE 登入原帳號；也可使用原 Email 帳號登入。不重複認領名冊。
- 已登入：直接回到原返回目的地，不要求重填資料。

舊 `/member-lookup` 連結會轉到 `/register?intent=existing_member`，保留安全的站內返回目標與保持登入選擇。電話及 Email 不放進網址。切換到既有帳號登入會清除該步驟的同意狀態，且送出的 LINE 請求不帶 `member_claim`。

## 身分與相容性

本次只整合前端入口。原 LINE OAuth、名冊有效性／重複認領檢查及 Email 所有權驗證維持原規則。知道電話與 Email 不會直接授予社員資格。已連結的 LINE 沿用原帳號與會籍；未連結的 LINE 仍依原一般登入流程處理，不由前端自行認定社員。

舊 `POST /v1/auth/member-lookup` API 保留相容性，網站入口不再呼叫它。原 API 的行為如下，供既有工作與維運參考：

公開 `POST /v1/auth/member-lookup` 只驗證格式、限流及排入加密工作，一律回覆 202「查詢已受理，請查看填寫的 Email。」與 `Cache-Control: no-store`，不在公開回覆揭露姓名、社員編號或是否匹配。

IP 與正規化 Email 雜湊各限每小時 5 次。首次處理工作才讀取最新名冊與會籍，寄送前加密保存固定信件內容；後續重試沿用同一內容與寄送冪等鍵。手機及 Email 加密保存，成功或終止重試後清除；信件不附姓名、手機、社員號、股籍或帳號 ID。

目前沿用單程序限流，若增加 API 實例須一併使用共用限流儲存。

## 驗證

`tests/browser/member-lookup.mjs` 與 `tests/browser/line-member-entry.mjs` 共 13 項隔離瀏覽器測試通過，涵蓋手機／桌機、新舊入口、首次認領、既有帳號直接登入、同意狀態重設、返回位置與登入偏好、核對錯誤及已登入狀態。測試拒絕外部網路，不進入真實 LINE 授權、不寄信、不建立真實帳號；並確認網站流程不再呼叫獨立查詢 API。
