# 共同購買新增商品與日常上架分流

日期：2026-10-28

## 問題與調整

自訂「高麗菜」提案原本只能選既有商品開團；誤選醬油後，提案仍顯示高麗菜，但實際訂單商品及單位變成醬油／瓶。

- 管理員直接開團的商品選單新增「其他／新增商品」。自訂提案預先帶入需求名稱及內容，需明確填寫單位、分類、稅別及價格。
- 商品、正式共同購買、提案狀態、稽核及通知事件同一交易提交，避免失敗留下孤兒商品。
- 提案卡顯示實際供應商品；門檻與限購一律使用商品單位。
- 商品啟用與「上架日常選購」分開。既有商品保持原設定；團購內新增商品預設不上架日常選購，管理員可之後在商品主檔上架並填庫存。
- 未日常上架商品不能一般下單，既有未付款一般訂單只能減量；共同購買仍可正常加入。
- 「審核截止」改稱「管理員處理提醒日」，開團時收在提醒設定內；保留付款截止後審核、預設 3 天提醒及逾期不自動退單退款的規則。
- 長商品名稱不再因加上團名尾綴超過 120 字而無法開團。

既有錯綁的正式團購未自動改品、取消或重新開團；需核對實際商品、單位與價格後再處理。

## 驗證

- 相關後端 173 項測試通過：權限、schema、原子回滾、既有資料遷移、日常／共同購買分流及舊訂單改量。
- Node 測試 100 項、TypeScript 與 Vite build 通過。
- CUA 隔離 UI 實測：高麗菜直接開團、顆單位、每人 5／門檻 6、即時刷新商品；日常選購不顯示，管理員另行上架並設定庫存後才出現。
- 手機 390px 表單無水平溢出；正式環境僅唯讀核對既有錯綁，不寫入測試商品、不收款、不開票。
- 獨立 code-review 找到長名稱邊界並已修正，其餘指定交易與分流範圍未發現可重現衝突。
- 追查上一版 CI 隨機失敗：發票隱私測試用四位數子字串搜尋整份 JSON，誤中合法 UUID／時間。改驗證敏感欄位與完整值，加入同數字公開標題回歸情境；取餐／發票相關 23 項通過，未修改正式 API 行為。

## 部署相容

遷移 `0039_product_daily_sales` 新增非空布林、server default true，保留舊商品及舊 INSERT 行為。需後端及遷移就緒後，再發布前端新入口。舊前端即使看見新商品，庫存預設 0 且新後端一般下單門禁會拒絕；舊 API 不支援 `new_product`，不得用舊 API 驗收新功能。
