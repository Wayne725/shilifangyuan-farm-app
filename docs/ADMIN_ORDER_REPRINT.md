# 管理員便當訂單補印

日期：2026-11-06

## 需求與行為

| 需求 | 實作 |
| --- | --- |
| 已退款不要顯示便當取餐與退單 | 已退款、已取消或有取消時間時隱藏入口；發票與付款查詢保留 |
| 管理員可以再次出單 | 訂單營運的便當訂單卡新增「再次出單」，預覽後填寫原因並送印 |
| 只允許已確認付款且未取消訂單補印 | 未付款、退款中、已退款與已取消不可補印。已付款且未結束取餐印訂餐單；已付款歷史已取餐等紀錄印「請勿製作」，不附取餐碼 |
| 舊訂單沒有列印工作也能列印 | 從目前訂單品項、選項及取餐資料建立快照，不依賴過去的出單工作；缺少的歷史取餐資訊如實標示未指定 |
| 避免重複送印 | 同一要求重試回傳原工作；等待發送／正在發送阻擋另建；結果未知須先核對紙本並確認可能重複 |

範圍是便當訂單。一般商品訂單沒有使用這個出單入口。此功能不修改付款、發票、庫存、取餐資格或退單狀態。

## 操作

1. 開啟 `/admin?section=orders`，搜尋便當訂單。
2. 按「再次出單」，查看紙本預覽與目前狀態。
3. 填「出單原因」。若之前送印結果待確認，先核對紙本並勾選重複列印確認。
4. 按「確認送至出單機」。模擬環境顯示「確認模擬出單」。
5. 查看工作狀態。雲端已接受不等於紙本已印出；斷線後可查詢或重試同一筆送印。需要另一份時，確認紙本後按「再印一份」。

## 資料與衝突防護

- 新增 `reference` 出單種類；不放寬自動製作單的付款守衛。
- 預覽識別摘要涵蓋訂單內容、狀態及出單設備。送出前若有變更，要求重新預覽。
- 管理員送印要求、工作及稽核同交易保存；請求 UUID 去重，前端在送出前存於目前分頁工作階段。
- 預覽、建立工作、實際送印都核對已付款與未取消；舊排隊紀錄單也適用。紀錄單送印時呈現最新狀態並保留「請勿製作」。所有手動補印失去付款或有效訂單資格即停止發送。
- 未付款／退款後仍可依原要求 UUID 查詢既有結果；重試回傳已建立工作，不建立第二張。前端保留查詢，移除重送／另印操作。自動取消通知維持原流程，以提醒廚房停止製作。
- 電話／Email 及列印內容沿用加密儲存；API 只允許管理員讀取與操作。
- 入站回應未知不自動另建工作；飛鵝送印結果未知也不自動重送。

## 驗證

- `tests/browser/admin-order-print.mjs`：手機／桌機、未付款／退款／取消入口隱藏、已付款補印、權限、過期預覽、送印中阻擋、斷線／重整去重、再印確認、模擬模式。
- `tests/browser/admin-order-cancellation.mjs`：退款／取消入口隱藏，發票與付款查詢仍可操作。
- 後端測試涵蓋最新快照、狀態競爭、送印資格、取消通知、冪等與加密；完整 CI 與正式部署結果另記於交付紀錄。
- 隔離測試不向實體出單機傳送資料；正式紙本結果需另行確認。
