# 交易恢復、安全與社務介面修復驗證

日期：2026-10-31。分支：`codex/remediation-completion`。整合基準 `434f35a` 同時保留先前安全／訂單單號修正與最新 `c5290c7` 飛鵝區域功能。本批尚未部署，沒有修改正式訂單、金流、資料庫或外部帳號設定。

## 本批結果

- 一般商品結帳先保存按帳號隔離的原始提交及 UUID；未知結果重整後只重送同一內容。新的購物車內容不會被恢復舊單的成功回應清掉。
- 後端原單回放先於關店、停售、售罄與變價檢查。相同識別、不同內容回 409；跨帳號隔離；跨便當／共同購買鍵不誤回另一種訂單。
- 建單同時驗證商品總額及完整報價指紋，抓出總額相同但品項單價、稅別或會籍變動；只更新報價，不自動再建單。舊單後來改量、改價或已付款時，先到訂單頁確認。
- 付款交接共用身分守衛，等待返回頁期間登出／換帳號就不開先前付款網址。同帳號憑證續期仍可完成交易。
- 提案建立及送審可恢復：資料庫按作者＋UUID 唯一，包含建立回應遺失、送審回應遺失、首次還原登入較晚與首次驗證失敗的保稿／修正流程。
- 平台設定保留未儲存內容，使用版本比對拒絕其他管理員的過期草稿；首次設定列不存在時也保護並行操作。
- 私人提案與留言等子資源使用相同可見性；成功登入只清本人帳號限流桶；應用及 Uvicorn access log 遮蔽能力憑證；供應商 CSV 重用共用防公式序列化。
- 非正式社員不再卡在提案載入；資格 503 可重試。首次登入還原與公開商品請求競態已固定時序重現並修正。
- Storage 受限時保留同頁操作與原 native 購物車，顯示實際儲存失敗狀態。送單識別不能持久化時不發 POST，避免重整後重複建立。

## 部署與相容界線

1. 本批只是可審查的修復版本。正式服務維持原狀；部署前仍需依整案追蹤完成必要檢查。
2. 先執行新增 nullable 欄位／唯一索引的 0041，再上相容後端，最後更新前端。前端平台設定需後端提供版本；避免先更新前端造成短暫不能儲存。
3. 舊 API 未帶 UUID、expected total／指紋者保留原行為，不宣稱有新版保護。共同購買 join 的新提交冪等仍需另一批完成；便當原有機制保持。
4. 指紋涵蓋商品報價，不包含後續物流費率。物流入口未因本批啟用。能力憑證遮蔽不等同已檢查所有例外內容、Render ingress 或外部日誌。
5. Storage 封鎖時無法保證跨重整持久化；付款提交因此先阻擋。IP 限流仍是單程序記憶體，跨 worker 配額待補。
6. 0041 一旦已有提案送單識別，禁止直接降版刪除；回復服務應保留新增欄位、採前向修正，避免失去防重複資訊。
