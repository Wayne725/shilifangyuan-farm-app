# 便當正式場次與測試付款保留

日期：2026-09-12

## 範圍

- 以正式已部署 `e68f23c` 為基底，僅發布線上付款相關修正。
- 不包含 `codex/cash-on-delivery` 的現場付款、現金收退款、貨到付款或 migration 0015；資料庫 head 仍為 `0014_invoice_account_binding`。
- 正式便當走有效 UUID 場次、原有 RayGate 正式付款、付款後取餐碼與汎宇正式發票流程。既有訂單發票帳戶快照不回填、不跨帳戶重送。
- 公開正式場次清單不列出三個禁止下單的展示場次，後台與歷史資料仍保留。
- 已取餐訂單禁止自行取消；不變更原有取餐時段或退款政策。

## 商品區測試付款

正式 `meals_only` 增加預設關閉的成對設定 `MEALS_TEST_PRODUCT_ID`、`MEALS_TEST_PRODUCT_SKU`。必須指定同一有效商品，DB 會員／一般價均為 NT$10，單品一件、合作社自取、不得混單或配送。建單、建立付款嘗試、付款跳轉三處共用檢核，既有 callback、查款及退款不受此新開關影響。

正式設定目標為 `PAYMENT-ACCEPTANCE-10`（金流與發票驗收品），不變更其他商品價格。保留最後一件商品的付款預留，不因建付款嘗試後庫存變零而擋住該筆跳轉。

## 新場次設定

使用者指定清華大學，菜單沿用展示晚餐九款原價、各 50 份，另加入既有「1 元正式付款測試商品」，標明不提供實體餐點。一元品沿用原測試容量 1 份。

展示模板的 UTC 時間轉台灣為 9/13 凌晨，與「9/12 今天晚餐」衝突，已請使用者確認今日截單及取餐起訖。在時段確認前不得擅自發布供餐承諾。新前端明確顯示日期與時間，避免只顯示日期掩蓋時段錯誤。

## 發布與驗收

正式 API 設定僅增加上述兩個非秘密值，不修改原 JWT、PII、RayGate 或汎宇憑證，不重新套用仍含 preview 值的 Blueprint。

發布前須通過前後端回歸與 CI，核对同一 commit 的 API／Web Live。模擬付款不代表新一元交易實付與正式開票已驗收；由使用者本人付款後再查訂單結果。不得自行新增正式付款、扣款、開票或核銷取餐。

本機驗證：後端 `tests audits` 994 項、前端／API 契約 31 項、Chromium 35 項均通過；TypeScript 與 Vite production build 通過；OpenAPI 路由維持 180 條。正式部署收據與 PostgreSQL 驗證結果另記，以上不等同實際扣款開票成功。
