# 訂單聯絡資料、現場收款與取餐日開票候選

日期：2026-11-07
狀態：本機候選，未推送、未合併至正式分支、未部署。

## 行為

- 後台訂單提供訂購者姓名與聯絡電話；電話沿用加密欄位，僅管理者介面解密。401／403及延遲回應不可恢復已撤銷權限的個資。
- 便當結帳新增選填聯絡電話。便當編號使用M＋台北日期＋每日序號；一般商品及團購使用O。舊訂單及金流交易編號保持不變。
- 已收款網站訂單可安排現在或取餐日開票。取餐日之前的背景工作、查詢或管理者重試不能提前出票；不倒填或預填發票日期。若背景服務整天未執行，恢復後使用實際開立日，不保證補回原活動日。
- 現場客人可輸入品名、含稅單價、數量、稅別及發票資料。收款產生真正訪客交易與操作員稽核，不歸入店員消費、會員免稅或點數。
- 現場交易使用持久UUID防重，瀏覽器只保存識別碼。重試相同內容重用交易，內容不同拒絕；全額退款保留紀錄並走既有發票作廢／結果未知查核。
- 原現金訂單缺少新欄位時保留外部POS契約。舊版送單資料新增空電話或預設開票方式後，仍可沿用原識別碼重送。
- 舊Render入口在沒有未完成購物／選餐、付款或登入回傳時導向正式自訂網域；既有付款返回及帶order_id的完成頁留在原網域。沒有將登入憑證放入網址，也不宣稱不同瀏覽器共享登入。

## 合併與驗證界線

保留正式功能基底a4354e4及安全候選1864f69c的兩邊變更，並以0049_merge_commerce_remediation接合兩條遷移歷史。既有遷移未改名；已有現場交易時拒絕會丟失客人／收款記錄的降版。

整合版已完成592項隔離後端回歸、158項前端單元測試、TypeScript及正式打包。PostgreSQL競態與真實遷移、管理端與結帳瀏覽器結果另由固定執行紀錄核對；不把原1864災難復原結果套用到新候選。

正式發票證明聯尚未啟用：既有汎宇流程是Email／手機載具，飛鵝型號及正式發票列印介面仍待確認。沒有將一般餐點小票標成發票，也沒有宣稱紙本已出。
