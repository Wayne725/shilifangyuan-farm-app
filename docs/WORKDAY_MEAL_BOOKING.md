# 工作日便當預訂

日期：2026-11-09

## 規則

- 一般便當依週一至週五、排程勾選日及官方工作日日曆供餐；國定假日、補假與週末不自動開一般便當。
- 每個一般場次於前一工作日 00:00 開放，最晚在取餐前一個日曆日 20:00（台灣時間）截止。管理員設定的較晚開放或較早截止仍有效。
- 管理員若設定更早的截止日，系統同步前移開放日，確保有可用的接單期間。
- 週一正常供餐：週五、週六、週日 20:00 前都能訂週一。
- 週一休假、週二供餐：從前一工作日開放，週一 20:00 截止。
- 長連假與跨年使用相同規則。畫面預設選最近可訂日期，不將「明天」寫死。
- 管理員可用「特殊日期加開」建立週末或假日場次。場次預設以前一天 20:00 為最晚截止。

## 管理入口

`管理者 → 訂餐營運 → 便當管理`

- 「每日午晚餐排程」維護自動場次。新排程預設週一至五；「立即補齊未來場次」可立即執行。
- 「場次」新增或編輯無訂單場次，選擇「工作日供餐」或「特殊日期加開」，確認後發布。
- 每日排程勾選「週六・只接受會餐」後，平常週六和補班週六都會自動加開會餐。政府日曆註記的假日會跳過，週五 20:00 截單。「接下來的週六會餐」可暫停單週新預訂。
- 停用排程不會自動取消已存在場次；單日停餐可由管理員取消該場次。已有訂單仍走既有退單／退款程序。
- 候選版的「停用排程」先列出已建立場次及未取消訂單數。可選擇只停止自動建立，或同時暫停這份排程中仍有預訂時段的場次接收新單。既有訂單照原安排付款和取餐。預覽後若資料有變動，重新核對再確認。

排程的取餐範圍至少須包含一個可選時段。午餐可選 11:00 至 13:00，晚餐可選 16:30 至 18:00，時段間隔為 30 分鐘。舊設定若沒有符合的時段，可在原排程中修正，系統會略過其新場次生成。

## 暫停單場接單

在「場次」選擇該場次的「暫停新預訂」。暫停期間，顧客仍可查看已成立的訂單，並依原期限付款和取餐。廚房可繼續備餐及出單。

只要場次仍有未截止的取餐時段，就可使用「恢復接單」。系統沿用場次原有的開放時間、備餐期限和會餐規則。

## 追加場次份數

場次已有訂單或已開放取餐時，可在「場次」選擇餐點追加可售份數。場次須仍有未截止的取餐時段。新份數加到該餐點的原總量，已付款及保留的份數仍計入總量。可完整編輯的場次從原場次編輯設定份數。

暫停接單的場次可以先追加份數，再依營運需要恢復接單。

## 僅開放會餐

新增週六或其他特殊日期場次時，可選「僅開放會餐」。這是單一場次的設定。接單最晚在取餐前一天台灣時間 20:00 截止，較早的場次截止仍有效。顧客依原會餐流程至少預訂 2 份，填寫抬頭與統編，於取餐日線上付款及開票，完成付款後領餐。

## 單場當日訂餐

管理員可在建立或編輯無訂單場次時，開放取餐當日訂餐。填入台灣時間的當日預訂截止和最短備餐分鐘數，再發布場次。已發布場次可按既有編輯條件調整。平日、特殊加開都能單場設定，排程產生的場次預設採前一日截止。

當日訂餐場次採線上付款。一般便當的每個取餐時段依當日截止及最短備餐時間決定可訂期限，並將較早時間存入訂單作為付款期限。超時付款或太晚確認的收款走退款流程。會餐仍在前一日 20:00 前完成預訂，取餐日付款及開立統編發票。

當日訂餐場次的一般便當由廚房完成備餐後標記待取餐。

## 官方日曆與維護

來源：[人事行政總處政府行政機關辦公日曆表](https://data.gov.tw/dataset/14718)。版本化保存 2025–2027 年每日資料、來源網址與 SHA-256；交易時不依賴外部網站即時連線。

`backend/app/data/taiwan_workdays_sources.json` 記錄來源及下載日期。每年新增官方年度資料時需核對完整年度、0／2 放假欄位、校驗碼，再跑 `test_workday_calendar.py`。補班週六依排程只開會餐。

日曆未涵蓋的日期不猜測為工作日；自動排程停止在資料邊界，管理員可確認後使用特殊日期。管理頁顯示資料涵蓋日期。

## 舊資料與交易保護

- `booking_policy` 區分舊場次、工作日與特殊日期。新政策的接單窗口直接存入場次，前台、報價、下單、未付款改量、線上付款及背景結束共用。
- 啟用排程中，未來沒有任何訂單、也沒有人工編輯紀錄的舊自動場次可轉換；假日場次退回草稿，所有轉換保留稽核紀錄。
- 有訂單、人工編輯、已取消／結束及手動特殊場次不自動覆寫。既有訂單價格、取餐安排及付款截止快照維持原值。
- 保留的舊自動假日場次停止接受新預訂；原訂單仍可依原期限付款，前台不再把該場次列為可選日期。
- 現場付款的實收期限、已付款整單退款重下、晚到付款與付款版本核對維持原流程。
- 已有新政策場次時，資料庫遷移不允許直接移除政策欄位，避免降版後把新訂單變成只能訂明天。

## 更新官方日曆

1. 從[政府資料開放平臺](https://data.gov.tw/dataset/14718)開啟人事行政總處最新的年度 CSV，記錄實際下載網址和取得日期。新版覆蓋同一年時，先比對變更日期、是否放假與備註。
2. 對下載原檔執行 `shasum -a 256 官方原檔.csv`，將結果記入 `source_sha256`。轉成 UTF-8 無 BOM，保留 `西元日期,星期,是否放假,備註` 四欄及每日紀錄，再存為 `backend/app/data/taiwan_workdays_YYYY.csv`。日期可用 YYYYMMDD，放假註記必須保留。
3. 確認全年每日恰好一筆（365 或 366 天），抽查一個國定假日、一般週六及有公布的補班週六。執行 `shasum -a 256 backend/app/data/taiwan_workdays_YYYY.csv`，同步更新 `taiwan_workdays_sources.json` 中的年份、檔名、原始下載網址、兩份 SHA-256、天數和取得日期。重新部署 API 後，在排程頁確認新年度。若官方修正已生成日期，先檢查既有訂單，再由管理員依場次處理。
