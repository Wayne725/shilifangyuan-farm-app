# 工作日便當預訂

日期：2026-11-09

## 規則

- 一般便當依週一至週五、排程勾選日及官方工作日日曆供餐；國定假日、補假與週末不自動開一般便當。
- 每個一般場次於前一工作日 00:00 開放，最晚在取餐前一個日曆日 20:00（台灣時間）截止。管理員設定的較晚開放或較早截止仍有效。
- 週一正常供餐：週五、週六、週日 20:00 前都能訂週一。
- 週一休假、週二供餐：從前一工作日開放，週一 20:00 截止。
- 長連假與跨年使用相同規則。畫面預設選最近可訂日期，不將「明天」寫死。
- 管理員可用「特殊日期加開」建立週末／假日場次、餐點、價格、容量與接單期間；本次仍以前一天 20:00 為最晚截止，不新增當日訂餐。

## 管理入口

`管理者 → 訂餐營運 → 便當管理`

- 「每日午晚餐排程」維護自動場次。新排程預設週一至五；「立即補齊未來場次」可立即執行。
- 「場次與核銷」新增或編輯無訂單場次，選擇「工作日供餐」或「特殊日期加開」，確認後發布。
- 停用排程不會自動取消已存在場次；單日停餐可由管理員取消該場次。已有訂單仍走既有退單／退款程序。

## 官方日曆與維護

來源：[人事行政總處政府行政機關辦公日曆表](https://data.gov.tw/dataset/14718)。版本化保存 2025–2027 年每日資料、來源網址與 SHA-256；交易時不依賴外部網站即時連線。

`backend/app/data/taiwan_workdays_sources.json` 記錄來源及下載日期。每年新增官方年度資料時需核對完整年度、0／2 放假欄位、校驗碼，再跑 `test_workday_calendar.py`。補班週六仍需管理員明確加開。

日曆未涵蓋的日期不猜測為工作日；自動排程停止在資料邊界，管理員可確認後使用特殊日期。管理頁顯示資料涵蓋日期。

## 舊資料與交易保護

- `booking_policy` 區分舊場次、工作日與特殊日期。新政策的接單窗口直接存入場次，前台、報價、下單、未付款改量、線上付款及背景結束共用。
- 啟用排程中，未來沒有任何訂單、也沒有人工編輯紀錄的舊自動場次可轉換；假日場次退回草稿，所有轉換保留稽核紀錄。
- 有訂單、人工編輯、已取消／結束及手動特殊場次不自動覆寫。既有訂單價格、取餐安排及付款截止快照維持原值。
- 保留的舊自動假日場次停止接受新預訂；原訂單仍可依原期限付款，前台不再把該場次列為可選日期。
- 現場付款的實收期限、已付款整單退款重下、晚到付款與付款版本核對維持原流程。
- 已有新政策場次時，資料庫遷移不允許直接移除政策欄位，避免降版後把新訂單變成只能訂明天。
