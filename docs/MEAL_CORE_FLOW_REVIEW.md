# 便當核心流程與高齡使用者檢視

日期：2026-10-08

本輪依程式、頁面資訊結構及資料規則檢視，對應 70 歲、不熟悉電商操作的使用者。沒有把未完成的瀏覽器點擊或真實交易寫成已驗收。

## 問題與本輪處理

| 使用情境 | 原本障礙 | 本輪調整 |
| --- | --- | --- |
| 找到能訂的日期 | 今天與多個未來日期同時出現，容易誤以為都能訂 | 只呈現台灣明天，並寫清楚「今天可訂明天」 |
| 選餐 | 場次圖片佔畫面、進入選餐後仍有縮圖 | 改成場次與餐點純文字條列，名稱、份數及價格在同一區 |
| 選時間 | 下拉選單需額外展開，仍列出 10 分鐘時刻 | 半小時大按鈕，包含 13:00／18:00，選後文字確認 |
| 知道下一步 | 英文步驟與取餐先選的順序不符口語需求 | 日期 → 餐點與份數 → 取餐時間 → 發票 → 確認明細 |
| 查看已訂內容 | 顯眼入口稱「取餐憑證」，明細在下方 | 改「我的便當訂單」，依取餐日期選單，明細與地點時間優先顯示 |
| 處理付款與退單 | 容易把發票延遲當作付款失敗，或以為送出申請就取消 | 付款、退單、發票分別顯示，申請前與FAQ明確說明管理員審核 |
| 尋求協助 | 使用說明小字約 10px，沒有集中FAQ | 說明至少 16px、操作項目至少 48px，新增常見問題及兩本手冊 |

## 核心導覽

「我要訂餐」／「我的便當訂單」／「需要幫忙」三個入口連接同一套流程。便當頁不提供運送方式或物流選擇；其他既有業務與歷史資料的去留由各自模組處理。

同一分頁草稿保留，資料改變會重新檢查；估價、最終報價、發票稅別及退單審核流程均沿用。管理員權限、出單機及外部授權的完成狀態以操作手冊與後端驗收結果為準。

## 仍需驗收

- 真實手機字級、時間按鈕、鍵盤與選餐後跳到明細的位置。
- LINE 授權返回後，使用者是否能辨認登入成功及社員身分。
- 付款返回、實際取餐核銷、退款及發票通知。
- 邀請實際高齡使用者完成一次預訂與一次查詢，記錄是否需要協助及卡住位置。
