# 交易修復與入社驗收發布

日期：2026-09-07

## 範圍與限制

使用者同意按「交易修復及回歸 → 入社測試 → 分批部署 → 雲端驗收」進行。本輪測試使用隔離資料庫、模擬供應商與假證件；不發起真實扣款、退款、開票、寄信或改動既有證件。

發布只納入交易管理、付款返回、入社選檔檢查與對應測試。不更改 migration、模型、依賴、Render Blueprint、方案、環境變數、汎宇正式／測試設定、Email 分工或既有背景排程；後端原有排程仍按原設定運作。

## 本輪發現與修復

1. 入社畫面標示 8MB，但選檔後先 `arrayBuffer()`，無本機尺寸／類型檢查。用失敗瀏覽器測試重現過大及 HTML 檔仍進入上傳流程，再增加前端檢查；後端原有 8MB、檔案種類、hash 與確認機制不放寬。
2. 汎宇文件存在表格與範例差異：《API說明文件》第 7 頁未列作廢 `notifyEmail`，《API範例V4.1》第 3 頁卻有。撤回先前未部署的移除，保留原 adapter 支援及預設空字串。以 B2C／B2B、成功／逾時四個公開管理 API 案例先失敗再恢復通過。開票通知仍由汎宇，不用平台信冒充。
3. 新增入社證件的公開 API 隔離驗收：別人不能確認／列出／刪除／取下載網址；管理員的申請與證件 ID 必須配對；刪除後不能再取得新下載網址。網址過期及雲端原件實際刪除需另做真實測試儲存驗收。

## 納入的既有修復

- 一般、團購、便當與入社付款先掛載原訂單／款項頁，再轉向供應商；上一頁不重建訂單。
- `/cart` 相容回新版結帳。
- 管理端訂單分頁搜尋、填原因查金流與失敗工作重試、全額退款作廢／結果核對。
- 作廢使用 `/cancelInvoice`，狀態未知只補查、不盲目重送；折讓仍暫緩。
- 更新開票時點說明，保留汎宇官方發票信與平台付款通知的分工。
